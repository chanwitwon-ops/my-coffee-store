# ระบบสั่งอาหารด้วยตนเองจากโต๊ะ (Dine-in Self-Order System)

- **วันที่บันทึก:** 2026-08-03
- **อัปเดตล่าสุด:** 2026-08-03 — เพิ่มหัวข้อ "หน้าจอแดชบอร์ดของพนักงาน" (สถานะการจ่ายเงิน + สิทธิ์แยกตามบทบาท)
- **อัปเดตล่าสุด:** 2026-08-03 — ยืนยัน requirement แล้ว: ตัดสินใจเรื่องช่องทางชำระเงิน (จ่ายหน้าเคาน์เตอร์ ไม่จ่ายในระบบ), fallback เมื่อ QR/เน็ตขัดข้อง, การแชร์ตะกร้าต่อโต๊ะ, และระดับรายงานผู้จัดการ ส่งต่อไปทำ design ที่ [[../../02-design/01-prototypes/20260803-02-dine-in-self-order|01-prototypes]] และ [[../../02-design/02-technical/20260803-02-dine-in-self-order|02-technical]]
- **สถานะ:** Confirmed
- **อ้างอิง:** -

## บริบท / ที่มา

ร้านกาแฟต้องการให้ลูกค้าสั่งอาหาร/เครื่องดื่มได้เองจากโต๊ะ โดยไม่ต้องรอพนักงานมารับออร์เดอร์ เพื่อลดภาระพนักงานและเพิ่มความเร็วในการบริการ

## ความต้องการ (Requirement)

- ลูกค้าสแกน QR Code ที่ติดอยู่บนโต๊ะ เพื่อเปิดหน้าเว็บสั่งอาหาร (ไม่ต้องติดตั้งแอป) QR แต่ละโต๊ะต้องผูกกับหมายเลข/ตำแหน่งโต๊ะ เพื่อให้ระบบรู้ว่าออร์เดอร์มาจากโต๊ะไหน
- ลูกค้าเลือกเมนู ปรับแต่งตัวเลือกได้ (ความหวาน, ไซส์, เพิ่มช็อต, ชนิดนม) ใส่ตะกร้า และยืนยันออร์เดอร์ — ทุกคนที่นั่งโต๊ะเดียวกันแชร์ตะกร้า/ออร์เดอร์เดียวกัน (ไม่แยกออร์เดอร์ต่อคน)
- **การชำระเงิน:** ลูกค้าจ่ายเงินที่หน้าเคาน์เตอร์ (เงินสด/บัตร) ไม่มีการชำระเงินภายในระบบในเวอร์ชันนี้ พนักงานเป็นผู้กดยืนยันสถานะ "จ่ายแล้ว" ในระบบเองหลังรับเงินจากลูกค้า
- เมื่อลูกค้ายืนยันออร์เดอร์ ระบบต้องแจ้งเตือนบาริสต้า/ครัวแบบเรียลไทม์ทันที (เช่น ผ่านหน้าจอในครัว หรือระบบแจ้งเตือนเสียง/visual) — ไม่ต้องรอสถานะการจ่ายเงิน เพราะจ่ายที่เคาน์เตอร์แยกจากขั้นตอนสั่ง
- พนักงานเห็นสถานะออร์เดอร์และหมายเลขโต๊ะที่สั่งมา และสามารถอัปเดตสถานะออร์เดอร์ได้ (เช่น "กำลังทำ" → "เสร็จแล้ว/เสิร์ฟแล้ว") ลูกค้าเห็นสถานะปัจจุบันของออร์เดอร์ตนเองด้วย
- **Fallback เมื่อ QR ชำรุด/อินเทอร์เน็ตที่โต๊ะขัดข้อง:** พนักงานรับออร์เดอร์ปากเปล่าจากลูกค้าแล้วกรอกเข้าระบบแทนให้ (ต้องมีหน้าจอ/ช่องทางให้พนักงานสร้างออร์เดอร์แทนลูกค้าโดยระบุหมายเลขโต๊ะเอง)

## หน้าจอแดชบอร์ดของพนักงาน (Employee Dashboard)

- แดชบอร์ดพนักงานแสดงรายการออร์เดอร์แบบเรียลไทม์พร้อมหมายเลขโต๊ะและสถานะออร์เดอร์ (ต่อยอดจากที่ระบุไว้ในหัวข้อความต้องการด้านบน)
- แสดง **สถานะการจ่ายเงิน** ของแต่ละออร์เดอร์ด้วย (จ่ายแล้ว/ยังไม่จ่าย) — พนักงานกดปรับสถานะเองหลังรับเงินที่เคาน์เตอร์ (ไม่ได้มาจาก payment gateway)
- สิทธิ์การเข้าถึงแยกตามบทบาท (role-based access):
  - **บาริสต้า:** เห็นเฉพาะคิวออร์เดอร์ สถานะออร์เดอร์ และสถานะการจ่ายเงิน เพื่อใช้งานหน้างาน
  - **ผู้จัดการร้าน:** เห็นข้อมูลเพิ่มเติมนอกเหนือจากบาริสต้า คือ **สรุปยอดขายรายวันแบบง่าย** — ยอดขายรวมวันนี้, จำนวนออร์เดอร์วันนี้, จำนวนออร์เดอร์แยกตามสถานะ (รอทำ/กำลังทำ/เสร็จแล้ว), จำนวนออร์เดอร์แยกตามสถานะการจ่ายเงิน (จ่ายแล้ว/ยังไม่จ่าย) เป็นข้อมูลสรุปแบบเรียลไทม์บนแดชบอร์ดเท่านั้น ไม่มีกราฟ/รายงานย้อนหลัง/แยกตามเมนู (เก็บไว้เป็น requirement รายงาน/analytics แยกในอนาคตตามที่ระบุใน Scope)
- อุปกรณ์ที่ใช้งาน: จอ/คอมพิวเตอร์ประจำเคาน์เตอร์ (ไม่ใช่แท็บเล็ตพกพา)

## ขอบเขต (Scope)

- **อยู่ในขอบเขต:** สั่งอาหารจากโต๊ะผ่าน QR Code (แชร์ตะกร้าต่อโต๊ะ), ปรับแต่งเมนู, ตะกร้าสินค้า, แจ้งเตือนบาริสต้า/ครัวแบบเรียลไทม์, การอัปเดต/แสดงสถานะออร์เดอร์, การปรับสถานะการจ่ายเงินโดยพนักงาน (จ่ายที่เคาน์เตอร์), พนักงานสร้างออร์เดอร์แทนลูกค้าได้ (fallback), สรุปยอดขายรายวันแบบง่ายสำหรับผู้จัดการ
- **ไม่อยู่ในขอบเขต:** การชำระเงินผ่านระบบ/payment gateway, ระบบสมาชิก/สะสมแต้ม, ระบบจัดการสต๊อกวัตถุดิบ, ช่องทางสั่งอื่นที่ไม่ใช่จากโต๊ะในร้าน (เช่น สั่งกลับบ้าน/เดลิเวอรี), รายงานยอดขาย/analytics เชิงลึก (กราฟ, แยกตามเมนู, ย้อนหลัง — อาจแยกเป็น requirement อื่นภายหลัง)

## Acceptance Criteria

- [ ] ลูกค้าสแกน QR ที่โต๊ะแล้วเห็นเมนูของร้านพร้อมตัวเลือกปรับแต่งได้ทันที โดยระบบรู้หมายเลข/ตำแหน่งโต๊ะจาก QR นั้น
- [ ] ลูกค้าสามารถเพิ่มสินค้าหลายรายการลงตะกร้าที่แชร์กันทั้งโต๊ะ ปรับจำนวน/ตัวเลือกปรับแต่งเมนู และยืนยันออร์เดอร์ได้สำเร็จโดยไม่ต้องชำระเงินในระบบ
- [ ] เมื่อยืนยันออร์เดอร์ ออร์เดอร์ต้องปรากฏที่หน้าจอ/ระบบของบาริสต้า/ครัวแบบเรียลไทม์ พร้อมหมายเลขโต๊ะ ทันทีโดยไม่ต้องรอสถานะการจ่ายเงิน
- [ ] พนักงานสามารถอัปเดตสถานะออร์เดอร์ได้ และลูกค้าเห็นสถานะปัจจุบันของออร์เดอร์ตนเองแบบเรียลไทม์
- [ ] พนักงานสามารถกดปรับสถานะการจ่ายเงิน (จ่ายแล้ว/ยังไม่จ่าย) ของแต่ละออร์เดอร์เองบนแดชบอร์ดได้ หลังรับเงินที่เคาน์เตอร์
- [ ] พนักงานสามารถสร้างออร์เดอร์แทนลูกค้าได้ (ระบุหมายเลขโต๊ะเอง) สำหรับกรณี QR/อินเทอร์เน็ตขัดข้อง
- [ ] ผู้จัดการเห็นสรุปยอดขายรายวันแบบง่าย (ยอดขายรวม, จำนวนออร์เดอร์, แยกตามสถานะออร์เดอร์/การจ่ายเงิน) บนแดชบอร์ด
- [ ] ระบบจำกัดสิทธิ์การเห็นข้อมูลตามบทบาท (บาริสต้า vs ผู้จัดการร้าน) ได้ถูกต้อง

## ประเด็นที่ยังไม่ชัดเจน (Open Questions)

- นโยบายเวลาที่ลูกค้าต้องจ่ายเงิน (จ่ายก่อนเสิร์ฟ vs จ่ายตอนจะออกจากร้าน) ยังไม่ได้กำหนด — เป็นนโยบายหน้าร้านที่ไม่กระทบ design เชิงเทคนิค ตัดสินใจได้ทีหลัง
- ไม่มีประเด็นอื่นที่บล็อกการทำ design ต่อ
